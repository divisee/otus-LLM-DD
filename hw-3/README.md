# Домашнее задание "Трекинг LLM-инференса с vLLM"

## Цель:
В этом ДЗ вы освоите полный цикл использования LLM в роли оценщика (LLM-as-a-Judge): от развёртывания собственной модели через vLLM, до настройки кастомной метрики оценки качества ответов с помощью MLflow. Вы научитесь вызывать модель через OpenAI-совместимый API, формировать запросы на оценку и анализировать поведение модели в роли "судьи".

## Описание/Пошаговая инструкция выполнения домашнего задания:
### Развёртка vLLM и локальное взаимодействие.

Развернуть vLLM с подходящий под ваше железо модели (CPU / GPU):
Вы можете использовать любую подходящую модель c hugging-face или другого ресурса, например:

* facebook/opt-1.3b (
* meta-llama/Meta-Llama-3-8B-Instruct
* HuggingFaceH4/zephyr-7b-alpha I (потребуется авторизация в hugging face)

*Основная задача - сделать модель доступной на выбранном порту локально, например - 0.0.0.0:8000*

### Взаимодействие с локальной моделью:
- Используя библиотеку для http запросов (httpx / requests / etc) обратитесь к модели и получите ответ (например с вопросом "What is the capital of Germany?").
- Сделайте тоже самое используя библиотеку openai (тут придется столкнуться с совместимостью OpenAI API и разных моделей, будьте внимательны).

### Mlflow и нтеграция кастомной genai метрики:
- Создать кастомную метрику (make_genai_metric) для оценки эксперимента используя локальную модель.
- Прогнать эксперимент на любом датафрейме с использованием локальной модели для расчета метрики.

## Формат сдачи:
- Пример кода файлами / репозиторий на Github / Gitlab / etc.
- Скриншоты работы vLLM, результатов ответа / docker compose по желанию.
- Скриншоты работы MLFlow, скриншоты вкладки Experiments и успешно запущенного эксперимента с использованием локальной модели.

## Критерии оценки:
Статус "Принято" состоит из следующих критериев:

- Корректность запуска и настройки vLLM-сервера — 20%. Модель должна быть успешно запущена локально или удалённо, доступна через OpenAI-совместимый API.
- Настройка MLflow Deployments и интеграция с моделью — 20%. Правильное указание endpoint’а, корректная регистрация метрики и ability to evaluate responses.
- Качество и адекватность кастомной метрики LLM-as-a-Judge — 25%. Грамотно сформулированный grading prompt, реалистичные примеры, логичная шкала оценки.
- Использование модели через API (requests/OpenAI client) — 20%. Корректная реализация запроса, обработка ответа, обёртка функции или тестовый вызов.
- Анализ и интерпретация результата — 15%. Наличие пояснений: как работает метрика, в чём поведение модели кажется адекватным или ошибочным.
- Дополнительные задачи: Использование модели с поддержкой chat-шаблонов (chat template) — +10%. Если в работе использована модель, которая корректно обрабатывает chat/completions запросы (например, mistralai/Mistral-7B-Instruct, zephyr, Llama-3-Instruct и др.), и это задокументировано в решении.
